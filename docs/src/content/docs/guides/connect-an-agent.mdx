title: Connect an agent
description: Point Claude Code, Claude Desktop, or another MCP client at xixo over OAuth.
---

At the end of this guide, an MCP client can search and file the catalog through `/mcp`. You need a
running xixo that is connected to masks, and an account in the masks tenant it signs in with. See
[agents and MCP](/concepts/agents/) for how the endpoint works.

## Allow dynamic registration in masks

An MCP client registers itself with masks the first time it connects. The masks tenant has to allow
that.

1. Open the masks console. With the built-in masks, it is at `/id/manage` on the tenant's origin.
2. Choose **Settings**, then **General**.
3. Under **Dynamic registration**, choose **On**, or **On, limited to these scopes**.
4. If you limit it, list `openid`, `profile`, `email`, `offline_access`, `xixo:catalog:read`,
   `xixo:catalog:write`, `xixo:web:read`, `xixo:web:keep`, `xixo:mcp:call`,
   `xixo:resources:read`, and `xixo:resources:command`.

A client asks for every scope xixo offers, and masks refuses the whole request when one of them is
outside the limit. To limit what a client may do, use the client's own controls, such as Claude's
per-tool permissions. `MASKS_DYNAMIC_REGISTRATION` on the masks deployment overrides the tenant's
choice.

## Connect Claude Code

1. Add the server, using your xixo address followed by `/mcp`:

   ```sh
   claude mcp add --transport http xixo https://xixo.example.com/mcp
   ```

2. Start `claude` and run `/mcp`.
3. Choose `xixo`, then authenticate.
4. Sign in to masks in the browser that opens, and approve the scopes.

`/mcp` in Claude Code then lists `xixo` as connected, with its tools.

## Connect Claude or another client

Any MCP client that supports OAuth and registers itself dynamically can connect. Give it the `/mcp`
URL, such as `https://xixo.example.com/mcp`.

In Claude:

1. Open **Settings**, then **Connectors**.
2. Choose **Add custom connector**.
3. Enter a name and the `/mcp` URL.
4. Sign in to masks and approve the scopes.

:::note
Claude Desktop reaches a custom connector from Anthropic's servers, so the address has to be public.
A `localhost` address works only for a client on the same machine, such as Claude Code.
:::

## What the token reaches

A client sees only the tools its token's scopes reach. `xixo:web:read` lets the `resource` tool
search the web, fetch a page, and look up weather and places. See the
[scopes reference](/reference/scopes/) for every scope, and the [MCP reference](/reference/mcp/) for
each tool.

## Check that it works

1. Ask the agent to search the catalog for a word you know is in it. It calls `search` and returns
   feeds with their ids.
2. Ask it to list resources. It calls `resource` with no key.

## If it doesn't work

The masks log shows each step the client took.

- **The client never opens masks.** Dynamic registration is off in the masks tenant. The masks
  metadata at `/.well-known/oauth-authorization-server` then has no `registration_endpoint`.
- **masks redirects back with `invalid_scope` and `this client may not request`.** The tenant's
  limit leaves out a scope xixo offers. Add the scopes it names.
- **The client gets `404`.** The address is missing `/mcp`.
- **`401` after signing in.** xixo refused the token, for example because masks issued it for a
  different tenant. xixo records each refusal with its reason under **Activity** in settings.
- **`503` from `/mcp` or `/.well-known/oauth-protected-resource`.** masks is not answering. The
  response body says why.
- **A tool is missing.** The token does not hold the scope for it. Authenticate again and approve
  the scope.
- **`429 too many requests`.** The token made more than `XIXO_MCP_LIMIT` calls in a minute, 120 by
  default.
