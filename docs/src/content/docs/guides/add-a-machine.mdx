title: Add a machine
description: Link up a machine with one command, approve it in xixo, choose what xixo may do with it, and attach the folders it shares.
---

This guide links up a machine, such as a home server or a desktop, and attaches the folders it
shares. The machine runs xixo link, which dials out to xixo, so the machine opens no port. See
[machines and xixo link](/concepts/resources/#machines-and-xixo-link) for how it works.

## Requirements

- An administrator's sign-in. Only an administrator sees a machine asking to link up and approves
  it.
- A route from the machine to xixo and to masks.
- On Linux: x86_64 or ARM64, systemd, `curl`, and `sudo` or a root shell.
- On macOS: Apple silicon or Intel. The command uses no `sudo`.

Run the command as the account that owns the folders. xixo link runs as that account and reads
only what it can read.

## Link up a machine

1. On **Resources**, choose the **Link up a machine** tile.
2. Check the system. The dialog shows the command for the system your browser runs on. Choose
   **macOS** or **Linux** to change it.
3. Check the folders. On macOS the command shares `~/Documents` and `~/Desktop`. On Linux it shares
   no folders. To change them, choose **Change** and type the folders, separated by spaces. End a
   folder with `:rw`, such as `/srv/inbox:rw`, to let xixo write into it.
4. Choose **Copy**.
5. Paste the command into a terminal on the machine and run it:

   ```sh
   curl -fsSL https://xixo.example.com/link.sh | sh -s -- ~/Documents ~/Desktop
   ```

6. Wait for the step that asks xixo to approve the machine. It prints a link and a code:

   ```text
   4. Asking xixo to approve this machine.
      Open this link to approve this machine:

        https://xixo.example.com/link/WDJB-MJHT

      Check that the page shows the code WDJB-MJHT, then choose Approve.
      This command waits until you do. The request runs out in 10 minutes.
   ```

7. [Approve the machine](#approve-the-machine). The command waits until you do, then starts xixo
   link and prints a summary, as in [check on a machine](#check-on-a-machine).

The command numbers its steps and prints each one before it starts. When `sudo` needs a password,
the line before it says why.

Each folder must exist, and cannot hold a quotation mark, an apostrophe, a backslash, a colon, or a
control character. Otherwise the command stops before it links up. On Debian or Ubuntu the command
also installs the programs that read PDFs, images, audio, video, and office documents. See
[installing](https://github.com/xixo/xixo/tree/main/link#installing) in the xixo link README for
every step it takes.

When the server holds no builds of xixo link, the dialog says so and shows no command. The server
image puts them in the folder `XIXO_LINK_DIR` names.

### Folders a Mac guards

macOS guards `~/Documents`, `~/Desktop`, `~/Downloads`, iCloud Drive, and removable and network
volumes. Until you grant access, the machine's card shows a warning that macOS has not let xixo
link read the folder. When a shared folder needs access, the command opens the Finder and the
settings for you.

1. Open **System Settings**, then **Privacy & Security**, then **Full Disk Access**.
2. Drag `xixo-link` from the Finder window into the list.
3. Turn on its switch.

The command lists these steps last, with the exact path to add. xixo link checks every 15 seconds
and starts reading the folder by itself. Running the link-up command again keeps the access and
says so. Only a xixo link too old to update itself is replaced, and then the command lists the
steps again. See
[xixo link on macOS](https://github.com/xixo/xixo/tree/main/link#macos) for more.

## Approve the machine

A machine asking to link up shows in the **Link up a machine** dialog at once. With the dialog
closed, a line above the machine cards says so, such as "studio is asking to link up."

1. Choose **Review**, or open the link the command printed. The link opens a page titled with the
   machine's name, such as **Approve studio**, with more about the machine.
2. Check that the code matches the code the command printed on the machine.
3. Choose **Approve**. Choose **Deny** for a machine you do not know.

:::caution
Approve a machine only when it shows the same code. Anyone who can reach xixo can ask to link up a
machine, and the code is how you know the request came from the machine in front of you.
:::

xixo adds the machine to **Resources**, and you become its first operator. Its name and its key
are the first part of its hostname, such as `studio`. The key is `studio-2` when `studio` is
taken. Once it connects, its card shows **online** beside its name.

While it waits, the command says once a minute how long the request has left. A request runs out
after ten minutes, and the command prints "Error: the request ran out before anyone approved it.
Run the command again." A denied machine prints "Error: an administrator denied this machine in
xixo. Run the command again to ask again."

## Check on a machine

The link-up command ends with a summary. `xixo-link status` prints the same one at any time, with
no `sudo`:

```text
media is linked up with https://xixo.example.com.

  In xixo    https://xixo.example.com/settings/resources/42
  Version    0.5.0
  Service    running
  Updates    automatic
  Folders    /srv/media  read only
             /srv/inbox  read and write

To check on xixo link:
  systemctl status xixo-link
  journalctl -u xixo-link -f
```

**In xixo** is the address of the machine's card. On a Mac the last two lines show the launch agent
and its log. `xixo-link help` lists the other commands.

## Change what xixo may do

Each machine's card has a choice an administrator changes at any time:

| | |
| --- | --- |
| **Search** | Browse, search, and read the text xixo drew out. |
| **Files** | Also fetch whole files and run its readers. |
| **Files and writing** | Also write into the folders it marks writable. |

The **Help read other machines' files** switch lets xixo send the machine uploads, cloud files,
web pages, and files other machines lend, to read.

A newly approved machine starts at **Search** with the switch on. The change takes effect at once,
without touching the machine. The machine's own config can narrow the choice, and then the card
says "Its own config holds back" and names what. See
[what xixo may do with a machine](/concepts/resources/#what-xixo-may-do-with-a-machine) and
[tools a machine offers](/concepts/resources/#tools-a-machine-offers).

## Attach a folder

1. On **Resources**, choose **Add to** followed by the machine's name, at the foot of its card.
2. Under **Folders it shares**, pick a folder. The list holds the ones not attached yet.
3. Check the name xixo filled in.
4. Choose **Attach it**.
5. Sync it like any other resource.

Only an administrator attaches a folder through a machine. A folder that overlaps one another
owner holds on the same machine is refused. Syncing while the machine is not connected leaves the
folder **offline** until xixo link is back.

A full sync that finds nothing in a folder where it found files before marks nothing gone, since an
unmounted disk looks the same as an emptied folder. Its items stay until a sync finds files again.

## Attach a model server it found

xixo link looks for Ollama and LM Studio on the machine, and the card shows a line such as "Found
Ollama on studio".

1. Choose **Add** on that line. xixo attaches the model server and checks it.
2. Open the menu on the new row, choose **Change**, and name a model for each role.

xixo reaches the model server at the machine's tailnet address when the server answers there. A
model server that answers only on its own machine is attached at `127.0.0.1` through the machine
itself.

When the line shows no **Add**, choose **Add to** followed by the machine's name, then **Set up**
under **Model servers it found**, and check the **Base URL**.

## Find machines on a tailnet

When xixo reaches a [tailnet](/guides/tailnet/), **Not linked yet** under the machine cards lists
the online machines on it that are not linked up.

- Choose **Link up** beside one to open the **Link up a machine** dialog.
- When a machine runs Ollama or LM Studio, the row says so, such as "Found Ollama". Choose **Add**
  to attach the model server through the tailnet.

## Change the folders

The folders live in the machine's own config, so xixo cannot widen them.

1. Run the link-up command on the machine again, with the new folders.

The machine prints "Already linked up as" followed by its name, and keeps its link and its
approval. Run with no folders, the command keeps the folders it has.

To change them by hand on Linux:

1. In `/etc/xixo-link/config.json`, change the `folders` list. A read-only folder is a path, such as
   `"/srv/media"`. A writable folder is `{"path": "/srv/inbox", "writable": true}`.
2. In `/etc/systemd/system/xixo-link.service`, change the `BindReadOnlyPaths=` line, where each
   folder is written as `"-/srv/media"`. A writable folder goes on the `BindPaths=` line.
3. Run `sudo systemctl daemon-reload`.
4. Run `sudo systemctl restart xixo-link`.

A folder in the config but not in the service is missing for xixo link.

## Give xixo link more memory

The service may use 2 GB of memory. To give it more for large office documents or video:

1. Run `sudo systemctl edit xixo-link` on the machine.
2. Add these lines:

   ```ini
   [Service]
   MemoryMax=4G
   ```

The setting lives in a drop-in file, so running the link-up command again keeps it.

## Keep xixo link up to date

xixo updates xixo link on each machine to the build the server ships, and the card says "updating
to" and the version. When a new build does not connect within three minutes, xixo link goes back
to the one before it, and tries again after six hours.

- To hold a machine at the build it runs, turn off **Update xixo link automatically** on its card.
  Turn it on again to update at once.
- A machine whose card says "Run the link-up command again so it updates itself" was linked up
  before xixo link updated itself. Run the [link-up command](#link-up-a-machine) once more. It
  keeps the link.

xixo link beside the server updates with its image. See
[updates](https://github.com/xixo/xixo/tree/main/link#updates) in the xixo link README.

## Files a machine cannot read

A file whose program the machine lacks, such as a PDF on a machine without poppler, waits, and the
card counts the files waiting. Do one of these:

- Install the programs on the machine, then run the link-up command again, which restarts xixo
  link.
- Choose **Files** for the machine, so a connected machine that helps read other machines' files
  reads a copy.

A file on a machine that is offline waits for the machine to come back.

## Rename a machine

1. Open the menu on the machine's card and choose **Change**.
2. Edit the name, or **Who operates it**, the masks subjects whose tokens may use the machine's
   tools, one per line.

The key stays the same.

## Remove a machine

1. Open the menu on each folder and model server reached through the machine, and choose
   **Put away**.
2. Open the menu on the machine's card and choose **Put away**.

Putting the machine away unenrolls it in masks, which revokes every token it holds, and closes xixo
link's connection. xixo link then stops and stays stopped. When masks cannot be reached, the machine
stays attached and the error says so. Try again once masks answers.

To delete what you put away, choose **Put away** at the top of **Resources**, then **Delete** on
each folder, then on the machine.

xixo link stays on the machine, stopped. To remove it, see
[uninstalling](https://github.com/xixo/xixo/tree/main/link#uninstalling) in the xixo link README.
