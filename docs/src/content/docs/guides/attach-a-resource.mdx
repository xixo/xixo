---
title: Attach a resource
description: Add storage, a model backend, a mailbox, a web source, or another resource from the browser app.
---

At the end of this guide, a new [resource](/concepts/resources/) is attached, checked, and in use.
You need `xixo:resources:command`, which the browser app asks for at sign-in. A resource everyone
can use also needs an administrator. See
[who changes a resource](/concepts/resources/#who-changes-a-resource).

**Resources** shows one card per machine. **This server**, the machine xixo runs on, comes first,
then each [linked machine](/guides/add-a-machine/). A folder or a model server sits on the card of
the machine it is on. A bucket, a mailbox, the web, and most other types are reached from **This
server**.

## Attach it

1. Choose your avatar in the top right corner, then **Resources**.
2. Choose **Add to** followed by the machine's name at the foot of its card.
3. Pick what to add:
   - Under **Model servers it found**, choose **Add** to attach an Ollama or LM Studio server in one
     step. A model server that answers only on its own machine is added through that machine, at
     `127.0.0.1`. Choose **Set up** instead to open **A model backend** with a **Base URL** to
     check.
   - On **This server**, under **Reached from here**, choose a group or **Everything**, then a
     type.
4. Under **Name it**, fill in the first field. The name must be unique among resources of that type,
   and it cannot be changed later.
5. Optionally, fill in **Called**, the name shown in listings.
6. Under **Who can use it**, choose **Everyone here** or **Only me**. See
   [a personal resource](#a-personal-resource).
7. Fill in the fields under **Connection**. Required fields are marked with an asterisk. Every
   type's fields are in the [resource reference](/reference/resources/).
8. Choose **Attach it**.

Only an administrator adds anything on a linked machine. A folder a linked machine shares needs no
step here, since it joins the catalog by itself. See
[folders it shares](/guides/add-a-machine/#folders-it-shares).

xixo checks the resource right away. When the check passes, the dialog closes. When it fails, the
resource is still attached, and the dialog shows **Attached, but it did not answer** with the error.
See [if it doesn't work](#if-it-doesnt-work).

A model backend added with **Add** has no models yet. Choose **Change** on its row to name a model
for each role.

:::note
**Places** with **Name where photos were taken** turned on sends each photo's coordinates to its
search server. It is off until you turn it on.
:::

## Connect an account through masks

**Google Drive**, **OneDrive**, and **An MCP server** with **Authentication** set to **Your own
account, through masks** use your own account. See
[resources connected through masks](/concepts/resources/#resources-connected-through-masks).

1. Attach it as above. The button reads **Attach and connect**.
2. Approve the connection in masks, and sign in to the provider if it asks.

The browser returns to **Resources**, and the resource syncs from then on. A resource that has not
finished connecting shows **not connected** and a **Connect** button. When the account stops
working, it shows **needs reconnecting** and a **Reconnect** button.

## A resource on a machine

A model server on a machine running xixo link is attached by itself when the machine's plan runs
models. See [a model server it found](/guides/add-a-machine/#a-model-server-it-found). To attach
one by hand, set **Reached through** to the machine under **Connection**, and give the address the
server answers at on the machine itself, such as `http://127.0.0.1:11434/v1`.

## Check it

Each row shows a resource's name and what it does. A storage resource also shows how many items it
holds. A row shows a state only when something needs you, such as **not working**, **offline**, or
**checking**, with the error below it.

1. Choose **Check** from the **⋯** menu on the resource's row.

A model server reads **checking** while xixo tries its models, and the row updates when that
finishes. xixo also checks every resource every six hours, and a failing or offline one every ten
minutes. **Details** on a row shows its key, type, what it does, its sync schedule, and when it was
last checked.

## Choose the defaults

A tenant has one default storage and one default model backend. The line at the top of
**Resources** names both, such as **Drops land in files on This server**. Only an administrator
changes them, and a personal resource cannot be a default.

- To make a storage resource the default, choose **Take drops** from its **⋯** menu. Uploads that no
  agent placed, and snapshots from the web, land there.
- To make a model backend the default, choose **Take questions** from its **⋯** menu. xixo prefers
  it when more than one resource could serve a role, and uses another while its check is failing.

## Schedule syncs

1. Choose **Details** on the resource's row.
2. Choose the schedule, such as **on demand**. A **Sync every** field opens.
3. Enter a number of minutes, or leave it empty to sync on demand only.
4. Choose **Keep**.

To sync now, choose **Sync now** from the **⋯** menu. See [syncing](/concepts/resources/#syncing).

## Change it

1. Choose **Change** from the **⋯** menu on the resource's row.
2. Edit **Called** or any field under **Connection**. A secret left empty keeps the value it holds.
3. Choose **Save it**.

The type and the name cannot be changed. xixo checks the resource again after saving.

## Watch pages on the web

A `web` resource takes each address on its **Watchlist** again every time it syncs. A page that
changed becomes a new version of its item.

1. Choose **Change** from the **⋯** menu on the web resource's row.
2. Enter `http` or `https` addresses under **Watchlist**, one per line, up to 100.
3. Choose **Save it**.
4. [Schedule syncs](#schedule-syncs) for the resource.

An address taken off the watchlist is marked gone after the next sync. An agent adds an address
with the `resource` tool's `watch` command and takes one off with `unwatch`.

## A personal resource

Choose **Only me** under **Who can use it** while attaching. You cannot change this later. The row
shows **only you**.

- Nobody else sees the resource or reaches it through a tool.
- What it syncs is cataloged for you alone.
- An agent uses it only in a run you started, and what that agent writes is cataloged for everyone.

**Google Drive** and **OneDrive** start as **Only me**. Without an administrator, **Only me** is the
only choice. See [only mine, or everyone's](/concepts/resources/#only-mine-or-everyones).

## Put it away

Choose **Put away** from the **⋯** menu on the resource's row. The resource stops syncing and is no
longer a default. What it cataloged stays searchable.

To bring it back:

1. Choose **Put away** at the top of the page.
2. Choose **Put back** on its row.

## Delete it

1. [Put the resource away](#put-it-away).
2. Choose **Put away** at the top of the page.
3. Choose **Delete** on the resource's row.
4. Read what it removes, then choose **Delete it**.

xixo stops pointing at what the resource cataloged and frees its key. An item found nowhere else is
forgotten, unless it has a note, a lifetime, or a tag or connection someone made. The files in the
source stay where they are. A resource that another resource is reached through cannot be deleted.

:::caution
A `database` resource keeps its files in xixo, so deleting it deletes them.
:::

## Over GraphQL and MCP

`attachResource` takes `type`, `key`, an optional `name`, `settings` with one entry per field,
`personal`, and `via`. `resourceTypes` lists each type's fields.

```graphql
mutation {
  attachResource(input: {
    type: "s3"
    key: "photos"
    settings: {
      endpoint: "http://minio:9000"
      force_path_style: true
      access_key_id: "xixo"
      secret_access_key: "xixoxixo"
    }
  }) {
    resource { id key healthy }
    checkError
    connectUrl
  }
}
```

For a type connected through masks, `connectUrl` is where to send the browser. The other buttons
have mutations of their own. See the [GraphQL reference](/reference/graphql/). Over MCP, the
`resource` tool lists and checks resources, and attaches one that needs no secret. See the
[MCP reference](/reference/mcp/#resource).

## If it doesn't work

- **`no inference origins are permitted — set XIXO_INFERENCE_ORIGINS`** or **`... is not one of
  XIXO_INFERENCE_ORIGINS`.** A model backend's **Base URL** must use an origin listed in
  `XIXO_INFERENCE_ORIGINS`. Add it, restart xixo, then choose **Check**.
- **`... does not serve ...`.** The model backend does not have a model it was given. Pull the model
  into the backend, or correct the name with **Change**.
- **`... resolves to ..., which is not a public address`.** xixo refuses private and local
  addresses. For object storage on a private network, list its origin in `XIXO_S3_ORIGINS`. See the
  [environment reference](/reference/environment/).
- **`... is needed`.** A required field was left empty.
- **That did not connect.** masks refused the connection, you declined it, or masks could not be
  reached. The message says which. Choose **Connect** to try again.
