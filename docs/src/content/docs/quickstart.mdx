xixo is an indexer for personal data. Try it on your own machine with `./dev`, run its container
image on a server, point an MCP client at it, or build on its GraphQL API.

## Try it locally

`./dev` runs the whole stack in containers. It needs Docker with Compose, Ruby, and a masks
checkout beside xixo for sign-in.

1. Clone both repositories side by side:

   ```sh
   git clone https://github.com/xixo/xixo.git
   git clone https://github.com/masksrb/masks.git
   ```

2. Start masks:

   ```sh
   masks/dev
   ```

3. Start xixo in another terminal:

   ```sh
   xixo/dev
   ```

xixo answers at `http://xixo.localhost:8180`, and these docs at `http://xixo.localhost:8181`.
`*.localhost` already resolves, so there is no `/etc/hosts` to edit. The stack serves one tenant,
`xixo`. See [development](/reference/development/) for the other commands, the ports, and
`./dev --multi`.

### Sign in

xixo has no accounts of its own. It signs people in through the masks dev stack at
`http://masks.localhost:12345`, whose setup token is `masks-dev`.

1. Open `http://xixo.localhost:8180`.
2. Click **Get started…**.
3. Sign in to masks with an account that may approve connections. On a fresh masks, enter the setup
   token `masks-dev` and create the first account.
4. Approve **xixo** when masks asks. You are signed in.

On later visits the button reads **Sign in**.

### Resources

The first time the stack starts, `db/seeds.rb` attaches resources to the tenant. They include
**Default storage**, which keeps uploads in Postgres up to 64 MB each, a MinIO bucket,
**Snapshots**, and **Local models**, which is Ollama on the host.

To see them all, click your avatar in the header, then **Resources**. To add another, click
**Add**, and see [attaching a resource](/guides/attach-a-resource/). `./dev seed` runs the seeds
again without deleting anything.

### Models

The models run on the host, outside the containers. `brew bundle` installs Ollama.

1. Start Ollama with a context large enough for the agent. The default of 4,096 tokens makes the
   agent lose the start of its prompt.

   ```sh
   OLLAMA_CONTEXT_LENGTH=32768 ollama serve
   ```

2. Pull the models the seeds name:

   ```sh
   ollama pull gemma3:4b
   ollama pull llama3.1:8b
   ollama pull qwen3:8b
   ollama pull nomic-embed-text
   ```

3. On the **Resources** page, click **Check** on **Local models**. The check names any model that is
   still missing.

Until the check passes, xixo analyzes files without summaries.

### The first file

Drop a file anywhere on the catalog. xixo stages it, analyzes it, and places it in a resource that
accepts it. The file's page shows the analysis as it runs. See [adding things](/concepts/adding/)
and [analysis](/concepts/analysis/).

## Run it with Docker

xixo ships as a container image, `ghcr.io/xixo/xixo`, which runs both the web process and the
worker. It needs Postgres and OpenSearch, and serves its own masks at `/id`. See
[self-hosting](/guides/self-hosting/).

## Connect an agent

Point an MCP client that supports OAuth at `/mcp`:

```sh
claude mcp add --transport http xixo http://xixo.localhost:8180/mcp
```

The client registers with masks and requests a token itself, so the masks tenant must allow dynamic
client registration. The tools the client sees depend on the scopes it is granted. See
[connecting an agent](/guides/connect-an-agent/) and the [MCP reference](/reference/mcp/).

## Build on the API

Everything the browser app does goes through `/graphql`. On a page that xixo serves, the `xixo`
package sends the session cookie and has a typed document for every operation the app uses:

```sh
npm install xixo graphql
```

```ts
import { createXixo, metaCSRFToken, SearchDocument } from "xixo";

const client = createXixo({ url: "/graphql", csrfToken: metaCSRFToken });

const { data } = await client.query(SearchDocument, { query: "lease" }).toPromise();
```

Any other client sends a masks access token as `Authorization: Bearer`. The token's audience is the
tenant's origin followed by `/mcp`, the same as an MCP client's token:

```sh
curl https://xixo.example.com/graphql \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"query": "{ search(query: \"lease\") { nodes { id title } } }"}'
```

See the [GraphQL reference](/reference/graphql/) for every field and the scope it needs.
