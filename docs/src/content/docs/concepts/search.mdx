---
title: Search
description: The OpenSearch index over every feed, and how lexical and semantic results are combined.
---

Every [feed](/concepts/feeds/) is a document in OpenSearch, at `OPENSEARCH_URL`. xixo indexes a feed
again whenever it or one of its [references](/concepts/references/) is saved, and whenever an
[analysis](/concepts/analysis/) of it finishes. The index is a copy. Postgres holds the records, and
a search returns ids that xixo loads from Postgres in ranked order.

A document holds the feed's type, mime type, tags, key, title, note, summary, text, and the paths
and resources of its originals. A file's tags, summaries, and text include those of its extracted
children. Paths, keys, titles, and tags are split on slashes, dashes, underscores, dots, and spaces,
so a search for `acme` finds `invoices/2026/acme-q3.pdf`.

## Lexical search

A query with text matches the title, key, and tags most strongly, then the note and summary, then
the paths and the text. Words in the title, note, summary, and text also match by their stems, so
`invoices` finds `invoice`. Common words such as `the` and `what` are left out of the query.

- Every word has to match, and the last word may match as the start of a word. A query of
  `acme inv` finds a feed that holds `acme` and `invoice`.
- When that does not fill the page and the query has three or more words, a looser search requires
  60% of the words. Its results follow the strict ones.
- A query with no text matches everything.

The `type`, `mime`, and `tag` facets narrow the results, and each takes one value or a list.

## Semantic search

Semantic search is added when the query has text, an inference resource names an `embedding` model,
and the page ends within the first 200 results.

xixo embeds the query and asks for the 200 nearest feeds. It keeps those whose cosine similarity is
at least `XIXO_SEMANTIC_FLOOR`, 0.55 by default, and within 0.12 of the best match, so a query whose
meaning matches nothing well adds nothing. When no facet is set, xixo also asks for the 200 nearest
[passages](#passages) and ranks their feeds by their best passage. This finds a long document by
something said deep inside it. The `search` tool shows each result found this way with its passage.

The lexical and semantic lists are fused by reciprocal rank fusion, which uses only each result's
rank in each list, since the two engines score on different scales.

Search is lexical only past the first 200 results, when no resource serves the `embedding` role, or
when embedding the query fails.

## Listing without the index

The `feeds` query lists feeds from Postgres, newest first, without OpenSearch. It narrows by type,
mime type, resource, tag, the feed it is connected to, and whether a feed was extracted from
another. The catalog uses it to list the feeds connected to the one selected. See the [GraphQL
reference](/reference/graphql/).

## Embeddings

Every minute, xixo embeds the feeds that changed since they were last embedded. A feed's vector is
made from its title, tags, summaries, note, and the start of its text. Changing a title or a note,
finishing an analysis, or saving a reference embeds the feed again, unless that text is the same.

Some embedding models match poorly without a prefix on each text. xixo adds the ones that
`nomic-embed-text`, e5, mxbai, bge, and snowflake-arctic-embed expect. A model backend's **Query
prefix** and **Document prefix** replace them.

Vectors made by two models, or with two prefixes, cannot be compared. When the model or a prefix
changes, xixo embeds every feed and passage in the tenant again. The vector's length is
`XIXO_EMBEDDING_DIMENSIONS`, 768 by default, and the embedding model must return that many.

## Passages

A feed whose text is longer than 1,500 characters is also cut into passages of up to 1,500
characters. A passage never crosses into the next section of the feed's outline, such as a sheet of
a workbook, a heading, an event in a calendar, a page of a PDF, or a minute of a transcript. Within
a section, a passage ends at a paragraph, a line, or a sentence when it can, and the next one starts
a little before it ends. A feed is cut again only when its text changes.

Each passage is embedded with its feed's title and its section's name, such as
`elm-street-pantry-plan.xlsx › Buy List`, and kept in an index of its own. The `feed` tool's `find`
returns a long document's passages that hold the words asked for, together with the passages nearest
in meaning.

## Tenants

All tenants' documents share one index. Each tenant searches through its own alias, which filters on
the tenant, and the nearest-neighbor query repeats that filter. xixo refuses a search with no
tenant. Each document also lists its readers, and every query filters by them, so a person's
[personal files](/concepts/resources/#only-mine-or-everyones) never reach anyone else's results.

## Rebuilding

xixo stores a stamp of the index's settings and mapping in the index itself. Every ten minutes, when
the stamp has changed or the index is missing, xixo builds a new index and reindexes every tenant
into it, under a run of kind `reindex`. It promotes the new index only when it holds as many
documents as there are feeds. Promotion moves every alias at once and deletes the old index. If it
fails, the old index keeps serving. Feeds that changed during the rebuild are indexed again
afterward.
