title: Feeds
description: The record for each thing in the catalog, and the edges that connect feeds.
---

A feed is the root record in the catalog. Files, notes, addresses, tags, and content types are all
feeds. A feed's [references](/concepts/references/) record where its bytes live, and its
[analyses](/concepts/analysis/) record what xixo found in it.

| Type | What it is | Singleton |
| --- | --- | --- |
| `xixo:file` | Bytes stored in a resource, or staged until a resource takes them. | No |
| `xixo:note` | Text written into the catalog. | No |
| `xixo:address` | An address, such as `/buy`, that can run on a schedule. | Yes |
| `xixo:tag` | A label that a person, an agent, or an analysis filed something under. | Yes |
| `xixo:mime` | A content type, such as `text/markdown`. | Yes |

## Keys

Every feed has a `key` of at most 900 characters. A file's key is its filename and a note's key is
its title. Keys do not have to be unique, so two files named `invoice.pdf` are two feeds.

A singleton is unique on its type and key, so a tenant has one `/buy`, one tag named `receipts`, and
one `text/markdown`. A tag's key ignores case and reads underscores as spaces, so `Acme` and `ACME`
are one tag, and so are `Mortgage_Statement` and `mortgage statement`.

An address key is a slash followed by up to 63 lowercase letters, digits, and dashes, starting with
a letter or a digit. Paths that xixo already serves, such as `/graphql`, `/mcp`, and `/uploads`, are
refused.

Content types are feeds of their own, so the tag list holds only labels that someone chose.

## Lifetime

A feed lasts forever unless it has an expiry. Every hour, xixo forgets the feeds whose expiry has
passed. Forgetting removes the feed's references, analyses, and edges, and deletes any bytes xixo
made for it. This suits things that go stale, such as a forecast, a price, or an API response.

- When an agent answers a question, anything it creates or keeps, such as a note or a page snapshot,
  lasts 30 days. Keeping something that already existed leaves its lifetime unchanged.
- Outside a question, anything a tool creates lasts forever.
- An agent can pass `lasts` as `forever` or as a number of days to change either default, and the
  `feed` tool's `last` verb changes the lifetime of something its run created.
- A person changes the lifetime of any feed with **Keep forever** on the item's page, or with the
  `setFeedLifetime` mutation.

A file whose every original has been gone from its source for 30 days is forgotten too, unless
something keeps it. See [noticing what is gone](/concepts/references/#noticing-what-is-gone).

## Parents and children

Some files contain other files, such as an email with attachments. Each file an analyzer extracts
becomes a `xixo:file` feed whose `parent` is the file it came from, and is analyzed in turn.
Extraction stops four levels below a top-level feed. Destroying a feed destroys its children.

## Edges

An edge connects two feeds. Edges have no direction and no label, a pair is stored once, and a feed
cannot connect to itself.

Tags and content types are built from edges. Filing a file under `receipts` connects the file to the
`xixo:tag` feed keyed `receipts`, and analysis connects every file to the `xixo:mime` feed for its
content type. Destroying a feed deletes all of its edges. A tag or content type that nothing is
connected to any more is deleted, unless someone wrote a note on it.

A finished analysis files its feed under the tags in its summary. Those edges are marked `inferred`.
The next analysis replaces them with its own, and leaves the edges a person or an agent made.
Tagging a feed by hand with a tag analysis found makes that edge a person's, so it stays. A failed
analysis keeps the tags the feed had.

Analysis and the `connect` tool both refuse a tag that would not help someone find a file again:

- fewer than two letters or digits, or more digits than letters;
- a date, an email address, a domain, or a citation such as `feed 12`;
- the feed's own key or title, or a name that contains a camera's file name, such as `GIG 2081` for
  `GIG_2081.NEF`.

So `NEMA 14-50R` is a tag, and `$2,409.33`, `June 2026`, and `GIG 2081` are not. Amounts, dates,
account numbers, and addresses stay searchable in the text. See [tag items](/guides/tag/).

## Schedules

An address has no bytes to read, so its work is a prompt. Its schedule holds:

| Field | |
| --- | --- |
| `prompt` | What the address should find. Required. |
| `turns` | The agent's turn limit for one run, six by default. |
| `interval` | At least 60 seconds, or empty to run only by hand. |
| `paused_at` | Set to stop the schedule while keeping its interval. |

Only an address can have a schedule, and it has at most one. Every minute, xixo analyzes each
address whose schedule is due, with the cause `schedule`, and sets its next run one interval later.
