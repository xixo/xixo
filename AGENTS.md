# Agents

## Writing

All prose in this repo follows [docs/STYLE.md](docs/STYLE.md), which is based on
the Ruby on Rails guides and organized by [Diátaxis](https://diataxis.fr/). That
includes the docs, the READMEs, and the descriptions the reference pages are
generated from: GraphQL descriptions, MCP tool descriptions, and
`lib/reference_pages`.

- Write plain, declarative sentences in the present tense, in American English
  with the Oxford comma.
- Leave out contrast framing ("X, not Y", "rather than"), closing aphorisms,
  fragments for rhythm, em dashes as general punctuation, metaphor, filler,
  and rhetorical questions.
- Write each page in one Diátaxis mode: the quickstart is a tutorial,
  `guides/` holds how-to guides, `concepts/` holds key concepts, and
  `reference/` is reference.
- `docs/src/content/docs/reference/` is generated by `bin/rails docs:reference`,
  except `environment.mdx` and `development.mdx`. Change the code the generated
  pages read, then regenerate. Never edit those pages by hand. `environment.mdx`
  and `development.mdx` are written by hand, and the same task fails when they
  and the code disagree, so a new `ENV` read needs a row in one of them: the
  server's in `environment.mdx`, the dev stack's, the seeds', and the tests' in
  `development.mdx`.
- Check every claim against the code before writing it down.
- The repo is public. Leave out real hostnames, addresses, and anything about
  private infrastructure.

## Releases

- Add first, remove later. A release may add tables, columns, indexes, enum
  values, jobs, and settings. It removes or renames one of them only in the
  release after the one that stopped reading it. The same holds for a key in a
  message between xixo and xixo link, and in a file the updater or xixo link
  reads. The updater rolls a server back to the build before, which then runs on
  the database the newer build migrated.
- A migration that moves data runs in the release that adds the new place. The
  release after removes the old one.
- CI checks the rule for the database with `script/rollback-rehearsal`. It
  starts the last release, migrates with this build, starts the last release
  again, and fails when `/up` fails or when a table or column the last release
  has is gone.
